# あとで見つかる（v0.5 段階2）

保育園の連絡帳・お知らせ・チラシ・写真を1か所にためて、あとから日付とキーワードで探せるWebアプリ（iPhoneのSafari向け）。

- 公開URL: https://ccwatode.github.io/atode-mitsukaru/
- 取り込み・検索・保存はすべて端末内（ブラウザのIndexedDB）で行い、外部サーバーやAI APIには送信しない
- このリポジトリにはアプリ本体とソースのみを置く。連絡帳データ・写真・サンプルPDFは含めない

## iPhoneでの使い方

1. Safariで公開URLを開く →共有ボタン→「ホーム画面に追加」
2. ホーム画面のアイコンから起動し、下の「＋」から追加
   - お知らせ一覧のPDF：Safariで「お知らせ」を開き、共有 →「オプション」→「PDF」で保存したもの。記事ごとに分けて取り込む
   - 写真：写真ライブラリから複数まとめて（撮影日を自動入力）
   - チラシ・配布資料：スクリーンショット・写真・PDF
   - お知らせの文章：コピーした文章を貼り付け（タイトルと日付を自動入力）
   - 連絡帳PDF：はいチーズ！ノートの画面をPDF保存したもの（複数選択可）
   - メモ
3. 「データ」→「バックアップを作成」→「ファイルに保存」→ iCloud Drive を選ぶ
   - 機種変更や削除のあとは「バックアップから復元」。今のデータは消えず、同じ記録は重複しない
4. お知らせ・チラシを開いて「予定を取り出す」→候補を確認して登録→「予定」タブで確認。予定の画面から iPhone／Googleのカレンダーに追加

## v0.5 段階2：お知らせ一覧PDFの取り込みとジャンル

| 区分 | 内容 |
|---|---|
| 取り込み | 利用者が手で保存した一覧PDFを、記事ごと（日付・題名・本文・写真・添付の名前）に分けて確認画面に出す。自動スクロール・自動展開などの自動取得はしない |
| ジャンル | 記事ごとにボタンで選ぶ。候補は「前回（同じ題名で選んだもの）」「提案（題名・本文からの推定）」「これまでに使ったもの」。新しく作ることもできる。同じ題名の記事はまとめて変わる |
| 重複 | 取り込み済みの記事は追加しない。本文が全文になった・写真が増えた記事は「更新」として選べる |
| 写真 | PDFに入っているJPEGはそのまま取り出して記事に付ける（描き直さない）。形式が違うものだけ描き直す |
| 添付 | 一覧PDFには名前と大きさしか入らないため、未保存として記事に付ける。あとから保存したファイルをまとめて選ぶと、大きさで元の記事を探して入れる。合わないものは勝手に入れずに尋ねる |
| 検索 | ジャンル・添付の名前・添付PDFの中の文字も対象 |
| 見た目 | 生成りの紙とテラコッタを基調に配色を整理（ライト／ダーク） |
| データ | ジャンルなどの項目を足すだけで、データベースの版は上げていない |

## v0.5 段階1：データ構造の拡張と移行

| 区分 | 内容 |
|---|---|
| 移行 | データベースの版は上げず、記録と予定に項目を足すだけ（連絡帳は書き換えない）。v0.4 に戻しても開ける |
| 更新前の案内 | 初回起動で「バックアップを保存してから更新」を案内 |
| 分類 | 保護者向けの区分（思い出・成長記録／予定・重要通知／資料／日々の記録）をタイトルから自動推定 |
| 子ども | 記録の名前から子どもの一覧を作成。表記ゆれは「まとめる」で統合 |
| 写真 | 長辺2560px以下の画像は圧縮し直さずそのまま保存。中身のハッシュ値を記録 |
| バックアップ | 形式の版は3のまま、家族と子どもを追加。v0.5 のバックアップを v0.4 で復元できる |

## v0.4 の主な変更：予定・カレンダー

| 区分 | 内容 |
|---|---|
| 予定の取り出し | お知らせ・チラシ・メモ・連絡帳の文章から、日付・時刻・場所・種類（行事／提出・締切／持ち物・準備／休園／給食／予備日）の候補を作る。チラシのPDFは埋め込まれた文字も使う |
| 推測しない | 「中旬」「未定」や曜日が合わない日付は確定せず未選択。年を推定したときはその旨を表示 |
| 確認してから登録 | 候補ごとに内容を直してから登録。同じお知らせを再度取り込んでも重複しない |
| 変更・中止 | 日付・時刻が変わったお知らせは「登録済みの予定との違い」を表示し、更新するか選べる。中止の記載も検知。変更の記録を残す |
| カレンダー | 「予定」タブに月間カレンダーとこれからの予定。ホームに近いうちの予定 |
| 元のお知らせ | 予定から元のお知らせ・チラシ・PDFを開ける |
| 外部カレンダー | iPhoneのカレンダーへは .ics、Googleカレンダーへは作成画面を開くリンク。まとめて追加も可 |
| バックアップ | 予定もバックアップ・復元の対象（旧形式のバックアップも読める） |

## v0.3 の主な変更

| 区分 | 内容 |
|---|---|
| 共通受け箱 | 連絡帳／お知らせ／チラシ・資料／写真／メモを同じ時系列で表示。行事・子どもで整理 |
| 写真 | 表示用（長辺2560px）とサムネイル（400px）を保存。原本保存は設定で選択 |
| 検索 | 連絡帳・お知らせ・チラシの本文、画像内の文字（手入力）、ファイル名を横断検索 |
| バックアップ | 画像・元PDFを含む1つのZIP。復元は追加のみで上書きしない。最終バックアップ日時を表示 |
| PDF | PDFの長さ上限（約14400pt）で切れたことを検出し、続きのPDFの作り方を案内。複数PDFの一括取り込み |
| UI | タブ（ホーム・検索・＋・写真・データ）、月ごとのタイムライン、未取得日のまとめ表示、ダークモード |
| 移行 | v0.2 のデータはそのまま残る（DBに保存場所を追加するだけで、既存の記録は書き換えない） |

## 開発

`source/` にソースがある。npmレジストリに頼らず esbuild で直接ビルドしている。

```
cd source
npm install           # esbuild / react / react-dom / pdfjs-dist / typescript
node build.mjs        # dist/ に出力
node --test test/*.test.ts
python3 test/e2e_calendar.py dist <文字入りのチラシPDF> <出力先>   # 予定機能の画面テスト（架空データ）
python3 test/e2e_list.py dist <出力先>                          # 一覧PDFの取り込みの画面テスト（その場で作る架空データ）
npx tsc -p tsconfig.json --noEmit
```

新しい依存ライブラリは追加していない（ZIP・EXIF読み取り・画像縮小は自前の実装とブラウザ標準機能）。

## プライバシー

- 子どもの個人情報・写真・連絡帳PDFはこのリポジトリに置かない（`.gitignore` で除外）
- アプリは外部への通信をしない（初回読み込みとService Workerによるキャッシュのみ）。例外は利用者が「Googleカレンダーで開く」を押したときで、その予定の名前・日時・場所・説明がGoogleに渡る
- はいチーズ！への自動ログイン・自動取得・非公開APIの利用はしていない。取り込みは利用者が保存したPDF・画像・文章のみ
